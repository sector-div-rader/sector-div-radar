# 05-运行与运维

## 1. 本地运行前提

### 1.1 Python 环境

- 建议版本：Python 3.11
- 安装依赖：

```bash
pip install -r requirements.txt
```

### 1.2 可选环境变量

如果只是本地验证页面构建，最少只需要安装依赖和准备数据文件。

如果要完整运行 `main.py`，建议设置以下环境变量：

```bash
export EMAIL_USER="your_email@example.com"
export EMAIL_PASS="your_password"
export EMAIL_TO="receiver@example.com"
export TELEGRAM_BOT_TOKEN="telegram_bot_token"
export TELEGRAM_CHAT_ID="telegram_chat_id"
export FMP_API_KEY="fmp_api_key"
export CALLMEBOT_APIKEY="callmebot_key"
```

## 2. 本地运行方式

### 2.1 运行主流程

```bash
python main.py
```

行为说明：

- 若当前 HKT 小时为 `21`，则进入 Dashboard Only 模式。
- 其他时间默认进入 Full 模式，执行完整扫描与通知流程。

建议：

- 本地开发时若只想验证数据产物，可以临时修改 `is_dashboard_only()` 或在非 21:00 时运行并仅关注输出文件。

### 2.2 运行回测

```bash
python backtest.py
```

输出：

- `backtest_results.json`

注意：

- 该脚本会下载较长周期历史数据，耗时明显高于主流程。

### 2.3 生成 Dashboard

```bash
python build_site.py
```

输出：

- `index.html`

建议运行时机：

- 当 `history.csv`、`dashboard_data.json`、`backtest_results.json` 发生变化之后。

### 2.4 运行旧版脚本

```bash
python radar.py
python turnover.py
```

说明：

- 两者属于旁路脚本，不参与主工作流核心链路。

## 3. GitHub Actions 运行方式

### 3.1 触发时间

工作流文件：`.github/workflows/daily.yml`

- `0 22 * * *`
  - UTC 22:00，即 HKT 06:00
- `0 13 * * *`
  - UTC 13:00，即 HKT 21:00
- `workflow_dispatch`
  - 支持手动触发

### 3.2 工作流步骤

1. Checkout 仓库
2. 安装 Python 3.11
3. `pip install -r requirements.txt`
4. 运行 `python main.py`
5. 若为奇数月，运行 `python backtest.py`
6. 运行 `python build_site.py`
7. 将生成产物提交并推送

### 3.3 需要配置的 Secrets

建议在 GitHub 仓库中配置：

- `EMAIL_USER`
- `EMAIL_PASS`
- `EMAIL_TO`
- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_CHAT_ID`
- `FMP_API_KEY`

如果要在 CI 中运行旧版旁路脚本，另需：

- `CALLMEBOT_APIKEY`

## 4. 产物说明

## 5. 常见运行场景

### 5.1 只想更新页面

步骤：

1. 确认已有最新的 `history.csv`
2. 可选更新 `dashboard_data.json`
3. 运行：

```bash
python build_site.py
```

### 5.2 只想刷新回测数据

步骤：

```bash
python backtest.py
python build_site.py
```

### 5.3 想完整重跑一次日报流程

步骤：

```bash
python main.py
python build_site.py
```

如果希望页面包含最新回测结果，再补跑：

```bash
python backtest.py
python build_site.py
```

## 6. 排障手册

### 6.1 `yfinance` 数据为空或不足

可能原因：

- 市场未开盘或数据源波动
- 标的代码暂时不可用
- 某些周期历史不足

影响：

- 对应标的被跳过
- `scan_pivot()` 或 `scan_dual_lookback()` 返回空列表

建议：

- 单独打印相关标的的 `history()` 原始结果确认数据情况
- 重点检查 `4H` 重采样前的 `1h` 数据是否足够

### 6.2 FMP 财经日历失败

表现：

- `get_fmp_calendar()` 返回失败占位文案

检查项：

- `FMP_API_KEY` 是否存在
- 接口配额是否耗尽
- 网络是否可用

### 6.3 邮件发送失败

表现：

- SMTP 登录或发送阶段异常

检查项：

- `EMAIL_USER` / `EMAIL_PASS` 是否正确
- Gmail 是否允许相应 SMTP 发送方式
- 收件人地址是否有效

### 6.4 Telegram 发送失败

表现：

- 打印 `[Telegram] 失败`

检查项：

- Bot Token 是否正确
- Chat ID 是否正确
- 消息是否被 4000 字截断后仍包含异常字符

### 6.5 Dashboard 页面显示异常

优先检查：

- `history.csv` 字段是否完整
- `dashboard_data.json` 是否为合法 JSON
- `backtest_results.json` 是否存在或结构异常
- `build_site.py` 是否成功执行

## 7. 维护与扩展建议

### 7.1 若新增标的

优先改动位置：

1. `ALL_TARGETS`
2. 如需回测，更新 `backtest.py` 中的 `TICKERS`
3. 重新运行主流程和回测

### 7.2 若新增指标

建议改动顺序：

1. `calculate_custom_indicators()` 或回测版指标函数
2. 背离识别逻辑
3. `save_history()` 字段结构
4. `build_site.py` 表格展示
5. 本 Wiki 中的数据契约说明

### 7.3 若准备重构项目

优先级建议：

1. 拆分 `main.py`
2. 让胜率从 JSON 自动加载
3. 给 `build_site.py` 引入模板层
4. 为关键算法补充单元测试

## 8. 接手建议

如果你是第一次接手这个项目，建议按以下顺序阅读与验证：

1. `code-wiki/README.md`
2. `01-架构总览.md`
3. `main.py`
4. `save_history()` 与 `build_email_body()`
5. `build_site.py`
6. `backtest.py`
7. GitHub Actions 工作流

完成上述步骤后，再决定是否进行结构化重构。
